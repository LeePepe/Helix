# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Helix is a VSCode extension that provides AI-powered chat commands for:
- **`/fit-finish`** — Compare Figma designs against code implementations and generate mismatch reports
- **`/gen-code`** — Generate production-ready code from Figma designs using project design system constraints

It also ships a Claude Code **skill pack** under `skill/helix-skill/` that replicates the same workflows as Claude Code slash commands.

## Commands

```bash
# Development build (with sourcemaps)
npm run esbuild

# Watch mode
npm run esbuild-watch

# TypeScript type-check only
npm run compile

# Lint
npm run lint

# Run a single test file
npx vitest run src/path/to/file.test.ts

# Run tests with coverage
npm run test:coverage

# Run VSCode integration tests
npm run test:vscode

# Package extension as .vsix
npm run package
```

## Architecture

```
VSCode Chat Participant (helixParticipant.ts)
    │
    ▼
Task Orchestrator (TaskOrchestrator.ts / UnifiedFigmaTask.ts)
    │
    ├── Agents (domain intelligence — each agent has a markdown prompt in agents/prompts/)
    │   ├── FigmaAnalyzerAgent      — extract design tokens from Figma
    │   ├── DesignSystemAnalyzerAgent — map design to project design system
    │   ├── PlannerAgent            — plan code generation
    │   ├── CodeGeneratorAgent      — generate component code
    │   ├── ComparerAgent           — compare Figma vs implementation
    │   ├── IntentAnalyzerAgent     — optimize agent pipeline selection
    │   └── ReportGeneratorAgent    — format fit-finish reports
    │
    ├── Runtime (infrastructure wiring)
    │   ├── ExecutionContext — cancellation token + trace events
    │   ├── ArtifactStore   — versioned inter-agent artifact passing
    │   ├── ToolRegistry    — unified Figma MCP + LLM tool invocation
    │   └── StreamHandler   — VSCode chat response stream wrapper
    │
    └── Services (pure infrastructure, no business logic)
        ├── llmService      — LLM chat + JSON mode calls
        ├── figmaService    — Figma MCP server integration
        ├── fileService     — workspace file I/O
        ├── cacheService    — artifact persistence to disk
        └── configService   — reads helix.* VSCode settings
```

**Key data flow:** User invokes chat command → `helixParticipant.ts` routes to `TaskOrchestrator` → orchestrator runs `UnifiedFigmaTask` with a pipeline defined in `commandPresets.ts` → each agent reads from `ArtifactStore`, calls LLM via `llmService`, writes output back to `ArtifactStore` → final output streams to VSCode chat panel.

**Contracts:** All inter-agent data shapes are defined as Zod schemas in `src/contracts/`. Every agent validates its input and output against these schemas.

**Agent prompts:** Each agent's system prompt lives as a `.md` file in `src/agents/prompts/`. They are loaded at build time via a custom ESBuild markdown loader (`esbuild.js`).

## Skill Pack (`skill/helix-skill/`)

Three Claude Code skills that run the same workflows without the VSCode extension:
- **`helix/`** — Router skill; dispatches to fit-finish or gen-code based on user intent
- **`helix-design-system-init/`** — Generates `.github/design-system-guide.md` by analyzing the codebase and Figma rules
- **`helix-fit-finish/`** — Fit-finish comparison workflow
- **`helix-gen-code/`** — Code generation workflow

Shared reference prompts are in `skill/helix-skill/helix/references/`.

## Key Configuration

- **Figma MCP server:** Must be running locally at `http://127.0.0.1:3845/mcp` (configured in `.vscode/mcp.json`)
- **Design system guide:** `.github/design-system-guide.md` — generated by `helix-design-system-init`, consumed by fit-finish and gen-code workflows
- **Reports output:** `.github/helix/reports/`
- **VSCode settings prefix:** `helix.*` (model, report path, design system guide path, etc.)

## Testing Notes

- Tests use **vitest** with a mocked VSCode API at `src/__mocks__/vscode.ts`
- Integration tests have a 60-second timeout and run sequentially (`threads: false`) to avoid LLM rate limits
- Coverage reports go to `coverage/` in text, JSON, and HTML formats
